# 方法：从独立语料到可执行能力

## 1. 安全来源目录

`analysis/source_catalog.json` 以 SHA-256 而非下载文件名识别来源。分析器遇到未登记哈希或缺失来源会停止；公开清单只写安全 `source_id`、书目信息、哈希与提取质量。原书位于被忽略的 `sources_and_references/`。

## 2. 提取与正文边界

`analysis/analyze_corpus.py` 对 PDF 按页提取，对 EPUB 按 spine 提取。Anna 中译本从 `text/part0009.html` 起算正文；前置材料不进入画像。全文只写入 `analysis/output/raw/`，公开输出不含原文。

清洗只统一空白、排除纯页码并保留段落边界。分析同时记录 EPUB 成员数、mimetype/CRC 状态、replacement character 与 HTML 残留，避免把提取错误当成语言信号。

## 3. 独立画像

分析器分别保存 `cambridge_china`、`toynbee` 和 `anna_translation`。`historical_combined` 只包含两个历史集合；代码与验证器都拒绝把 Anna 并入总体平均。统计包括文本量、单元与段落数、句长分布以及预先声明的小型标记表频率，只用于提出近读候选。

## 4. 近读与能力卡

`analysis/select_close_reading.py` 为每个安全 `source_id` 生成分层定位，不复制正文。历史样本回答结构与解释问题；Anna 样本只观察文学语言组织，并做来源排除。规律进入能力卡前必须回答：观察到什么、解决什么写作问题、何时不适用、怎样验证改善、哪些内容必须留在原语料中。

## 5. 综合写作运行时

事实权限先区分事实、用户判断、计算或推导、推测与虚构。文体路由再决定正文先交付什么、材料怎样推进、最终落到哪里；正向表达规范负责对象与动作、关系承接、段落来由与去处、具体与概括。历史能力为分析型文章补充结构、机制、尺度和判断边界；文学语言组织只处理节奏、过渡、具体—抽象、叙述距离与叙述/反应/评述的衔接。

叙述强度按文体自动路由：通知、公文和报告克制，问答、解释与公众说明轻量，评论/随笔/历史评述中度，明确文学创作充分。强度不增加事实权限。正向表达以可观察关系为标准，不以大规模词表定义好坏。

## 6. 评测与迭代

每次修改正向表达规范、能力库或路由，都复跑起草、重写、想法落地、文体分流、语言组织和反向测试。评测同时看对象与动作、文体与落点、段落路径、结构解释、事实边界与语言组织；反向案例专门检查“没有套话但仍然空转”、只换标题未换信息顺序、把计算升级为因果、去掉连接词就失去关系，以及事实文本被小说化。统计差异只有得到近读支持并通过行为评测后，才可升级为能力。
