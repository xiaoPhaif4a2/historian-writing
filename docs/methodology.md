# 方法：从书籍到可执行写作能力

## 1. 提取与清洗

运行 `analysis/analyze_corpus.py`。它对 PDF 按页提取文本，对 EPUB 按 spine 顺序提取正文 XHTML，并将全文写入本地忽略目录。清洗只做保守操作：统一空白、排除纯页码、保留段落边界。OCR 误差不会被自动更正为所谓“风格”。

## 2. 描述而非印象化归因

分析报告记录可复查的聚合信号：文本量、可提取单元数、句长分布、连接词、因果词、限定词、比较词和时间尺度词。统计只能提出候选，不足以单独证明风格。

## 3. 近读与能力卡

运行 `analysis/select_close_reading.py` 从每个源文件的不同位置产生无引文定位队列。在候选信号的基础上，近读这些局部文本，确认它是否服务于写作功能。只有能回答以下四点的规律才进入能力库：

1. 文本中观察到了什么；
2. 它在写作中解决什么问题；
3. 它何时不适用；
4. 如何在新文章中测试它是否真的改善了表达。

## 4. 运行时使用

调用 skill 时，模型先识别任务类型与事实边界，再从能力库中选择少量适用能力。它选择的是功能，不是作者，不向用户暴露“混合了谁”。

## 5. 评测与迭代

每次修改能力库，都用同一组起草、重写、想法落地和反向测试复跑。规则必须同时改善可执行评分与盲评读感；只带来宏大腔调、事实越界或原意流失的规则应移除或降级。
